3-го избирательного округа (выборы депутатов Законодательного Собрания Санкт-Петербурга
VIII созыва, голосование **18–20 сентября 2026**) так, чтобы **каждое утверждение
подкреплялось источником**.

## Структура репозитория

- `docs/istochniki.md` — **аудит источников**: откуда собирать позиции и действия
  каждого кандидата (категории, конкретные URL, статус доступа, пробелы).

  тематические группы, `site:`-запросы, результаты и правила атрибуции.
- `docs/svo_deep_analysis_2026-09-18.md` — отдельный отчёт о глубокой адресной
  проверке Дудоладова и Луговского: личные действия отделены от партийного контекста.
- `docs/search_gaps_2026-09-18.md` — найденные поиском белые пятна по всем четырём
  кандидатам и новые источники по темам, которых не было в первоначальной матрице.
- `docs/search_gaps_second_pass_2026-09-18.md` — результаты второго поискового прохода:
  законодательная работа, локальные обращения, бизнес-контекст и ранний политический опыт.
- `docs/literature_gap_audit_2026-09-18.md` — аудит белых пятен по англоязычной
  научной литературе о кандидатах, низкоинформационных и местных выборах.
- `docs/information_architecture_2026-09-18.md` — научно обоснованная архитектура
  честного сравнения: одинаковый вопросник, профили, подотчётность, источники,
  коды неизвестности и предложение нормализованной схемы данных.
- `docs/profile_context_audit_2026-09-18.md` — повторный поиск индивидуального
  контекста по всем четырём кандидатам: найденные источники, партийный контекст,
  персональные каналы и оставшиеся пробелы.
- `docs/longread_todo.md` — план перехода от короткого обзора к подробному лонгриду:
  карта глав, группировка 79 тематических меток, задачи по данным, интерфейсу и проверкам.
- `data/longread_sections.json` — структура лонгрида: общая глава, хронология и одинаковые разделы по каждому кандидату.
- `data/literature_gap_audit.csv` — структурированный список универсальных и
  кандидат-специфических пробелов с приоритетом и следующим шагом.
- `data/issue_taxonomy.csv` — черновой единый вопросник по темам, относящимся к
  полномочиям ЗакСа; используется для будущего сопоставимого представления.
- `data/matriks.csv` — **матрица «утверждение → источник»** (главный файл;
  каждая строка: кандидат, тип, утверждение, дата, полный `source_url`, цитата,
  достоверность и уровень атрибуции).
- `data/candidates.json` — машиночитаемые профили кандидатов.
- `data/sources_catalog.csv` — машиночитаемый каталог источников.
- `scripts/check_sources.py` — локальная проверка полных URL и проверка доступности
  всех URL матрицы, каталога и вопросника с подбором снапшотов Wayback Machine для
  мёртвых ссылок (запускать на машине с обычным интернет-доступом).

## Как читать матрицу

- `tip`: `взгляд` (заявление кандидата) / `поступок` (конкретное событие, действие) /
  `партийный контекст` / `биография` / `бизнес` / `кампания` / `контекст`.
- `uroven_atributsii`: один из фиксированных уровней — `личное высказывание`,
  `личное действие`, `партийная активность`, `СМИ-пересказ`, `не найдено`. Уровень
  `не найдено` используется для конкретной проверенной публикации, где кандидат не
  назван/не цитируется, а не как утверждение о всей его деятельности.
- `source_url`: полный URL конкретной страницы, подтверждающей строку; ссылки только
  на домен, `-` и пустые значения не допускаются.
- `doverie`: `прямая` — первоисточник (свои слова кандидата, официальный документ,
  реестр); `косвенная` — через СМИ/пересказ.
- `status`: `подтверждено` / `нужно уточнить` (пробелы помечены в столбце `zametka`
  и являются планом дальнейшей работы).

По СВО персональные записи добавлены для Гладунова и Зверева. Для Дудоладова и
Луговского в проверенных источниках персональное подтверждение не найдено; партийные
материалы СР/КПРФ вынесены в отдельные строки с уровнем `партийная активность` и
не приписываются кандидатам.

## Статический сайт

В корне репозитория находится готовый к публикации сайт:

- `index.html` — семантическая HTML-страница сравнения;
- `styles.css` — mobile-first стили поверх Pico CSS;
- `app.js` — клиентская логика без фреймворка и сборки;
- `data/matriks.csv`, `data/issue_taxonomy.csv`, `data/candidates.json` — файлы, которые сайт загружает относительно адреса страницы.

Интерфейс сначала показывает подробный лонгрид: общие сведения об округе, хронологию и одинаковые главы по четырём кандидатам. Ниже остаётся отдельное сравнение по 8 одинаковым вопросам, а все 96 записей доступны в полном списке источников. 79 исходных тематических меток из матрицы распределены по главам лонгрида. На мобильном первый экран не занят верхним меню: навигация находится внутри страницы, а доказательства открываются по требованию.

Pico CSS подключается dependency-free через CDN по рекомендованному в официальной документации шаблону: [`@picocss/pico@2/css/pico.min.css`](https://cdn.jsdelivr.net/npm/@picocss/pico@2/css/pico.min.css). Собственные пути к данным не начинаются с `/`, поэтому сайт рассчитан в том числе на публикацию в подпути GitHub Pages вида `https://USERNAME.github.io/REPOSITORY/`.

### Локальный просмотр

`fetch()` не загружает CSV и JSON из `file://`. Запустите из корня репозитория обычный HTTP-сервер:

```bash
python3 -m http.server 8000 --bind 0.0.0.0
```

Затем откройте [`http://localhost:8000/`](http://localhost:8000/). Для проверки без сервера доступность файлов можно дополнительно проверить командой `node --check app.js` и скриптом `python3 scripts/check_sources.py`.

### Публикация через GitHub Pages

1. Отправьте изменения в репозиторий.
2. В настройках репозитория откройте **Settings → Pages**.
3. В разделе **Build and deployment** выберите **Deploy from a branch**, нужную ветку и папку `/ (root)`, затем сохраните настройку.
4. После публикации откройте адрес Pages. Файл `index.html` должен находиться в корне выбранной ветки; отдельная сборка или backend не нужны.

Актуальная последовательность создания сайта описана в [официальной документации GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site), а настройка источника публикации — в [документации о publishing source](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site). Для project site адрес имеет вид `https://OWNER.github.io/REPOSITORY/`; GitHub допускает публикацию из любой существующей ветки и `/ (root)` или `/docs`, поэтому для основного сайта после слияния выбирайте `main` и `/ (root)`. GitHub Pages всё равно выполняет внутренний deployment workflow, но проекту не нужен собственный build step.

После сохранения настройки откройте **Visit site** в **Settings → Pages**. Публикация может занять до 10 минут; это указано в [официальной инструкции просмотра опубликованного сайта](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site#viewing-your-published-site). Проверяйте, что на опубликованном URL открываются `styles.css`, `app.js` и файлы из `data/`: при ошибке загрузки сайт явно сообщит о проблеме.
